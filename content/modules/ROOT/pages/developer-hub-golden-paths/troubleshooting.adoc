Every entry below was hit while building the module on the cluster or is a known failure mode to watch for.
Terminal commands assume you ran the lab's first block, which sets `U`, `SVC`, `ORG` and `CICD`.

== `flag needs an argument: 'n' in -n` after the terminal reconnected

Symptom:: A command that worked a minute ago fails with `Error: flag needs an argument: 'n' in -n`.
Cause:: A reconnected terminal is a fresh shell, so `$CICD` is empty.
Fix:: Run the lab's first block again, then repeat the command.

== The template failed at "Publish the GitOps repository" with "repository already exists"

Symptom:: The task stops at *Publish the GitOps repository* (or *Publish the service repository*); its log shows `repository already exists [owner: {user}-svcs, repo: …]`.
Cause:: A Git server will not hold two repositories with the same name, and `{user}-svcs` already holds one from an earlier run.
Fix:: Run `ws prep developer-hub-golden-paths --yes`: it empties `{user}-svcs`, removes the catalog entry and purges the four namespaces. Then run the template again.

== The push did not start a pipeline run

Symptom:: `git push` succeeded, but `tkn pipelinerun list -n $CICD` shows nothing new after 30 seconds.
Cause:: Pipelines-as-Code runs only for a repository it knows: the `Repository` that the `ci` application creates, and the organization webhook that `ws prep` creates. Either is missing.
Fix:: Check both:
+
[source,sh,role=execute]
----
oc get repository -n $CICD
oc get secret golden-pac-secret -n $CICD -o name
----
+
No `Repository`: the `ci` application has not synced yet (wait a minute after creating the project) or the GitOps repository is not named `<service>-gitops`. No Secret: run `ws prep developer-hub-golden-paths` again, which re-creates the Secret and the webhooks.

== The release run failed at `resolve-image`: "No image was built from commit …"

Symptom:: A tag started `parasol-quote-{user}-release`, which failed in seconds; `resolve-image` says no image was built from the commit.
Cause:: The release promotes the image the build pipeline made from the tagged commit. You tagged it before its build run finished, or its build failed a gate.
Fix:: Wait until that commit's `parasol-quote-{user}-build` run reads `Succeeded` (`tkn pipelinerun list -n $CICD`), then tag the same commit with the next version and push the tag.

== Two release runs started for one tag

Symptom:: After deleting a tag and pushing it again, `tkn pipelinerun list` shows two `parasol-quote-{user}-release` runs at the same moment.
Cause:: Gitea delivers the tag deletion as a push too, and Pipelines-as-Code starts the release for it with the same commit.
Fix:: Nothing to fix: both runs promote the same digest, and the second finds stage and prod already running it. To avoid it, release under a new version instead of re-pushing a tag.

== `git push` from Dev Spaces seems to hang, or says "Authentication failed"

Symptom:: The terminal shows nothing after `git push`, or the push fails with `Authentication failed`.
Cause:: Dev Spaces asks for your Git credentials in an input box at the *top of the editor*, not in the terminal. A wrong password ends in `Authentication failed`.
Fix:: Look up and enter `{user}` and the workshop password. After `git config --global credential.helper store` you are asked once.

== The release is waiting for stage

Symptom:: The `promote` task prints `waiting for Argo CD to roll v… out in {user}-stage...` for minutes, then fails with `stage never picked up …`.
Cause:: Argo CD has not synced `parasol-quote-{user}-stage`. It normally syncs within seconds of the commit, through the organization webhook; without the webhook it polls every three minutes.
Fix:: Open the application in {student_argo_url}[Argo CD^] and click *Refresh*, then push the tag again under the next version. If it stays *OutOfSync*, its sync message names the problem.

== The CI, CD or Topology tab in Developer Hub is empty

Symptom:: The component page has the tabs, but they show no runs, no applications or no workloads, while `tkn pipelinerun list` and `oc get deploy -n $U-dev` show them.
Cause:: Those tabs are read by the portal's Kubernetes and Argo CD plugins, which need the platform's portal configuration: a read-only ServiceAccount, the cluster CA, and the attendees' Argo CD account. A portal restart also leaves them empty for a minute.
Fix:: Reload after a minute. If a tab stays empty, tell your instructor; the admin check is:
+
[source,sh,role=execute]
----
oc get pods -n rhdh
oc get secret rhdh-plugin-config -n rhdh -o name
----

== The links to the repository inside Developer Hub do not open

Symptom:: A repository link from the template's run page or the catalog leads nowhere.
Cause:: Developer Hub addresses Gitea by its in-cluster service, `gitea.ogsr-gitea.svc:3000`, which a browser cannot reach.
Fix:: Open the repository through the Gitea route: {gitea_url}/{user}-svcs/parasol-quote-{user}.

== The portal shows a blank page or "Sign In" does nothing

Symptom:: The Developer Hub portal will not load, or the tab shows a Keycloak sign-in form.
Cause:: The shared `backstage-developer-hub` pod is restarting, or your single sign-on session ended.
Fix:: Reload the page and click *Sign In*. If the Keycloak form appears, enter `{user}` and the workshop password.
