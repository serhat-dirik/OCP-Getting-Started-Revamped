=== Brief

image::gitops-fundamentals/gitops-fundamentals-01-push-vs-pull.svg["Push versus pull delivery: a pipeline pushing changes into a cluster from outside, compared with a controller inside the cluster pulling desired state from a Git repository and reconciling live state against it."]

*Push versus pull*

Most delivery pipelines push changes into a cluster: the pipeline holds cluster credentials and reaches in from outside. Once it finishes, nobody can say whether the cluster still matches what was delivered without inspecting the cluster itself.

GitOps inverts that. A controller runs inside the cluster, watches a Git repository, and pulls the desired state in. No external system holds cluster credentials, and Git remains the answer to "what is supposed to be running" — not only at delivery time, but continuously.

*Drift, and why Git wins*

Clusters get changed by hand under pressure. With GitOps, that change is no longer silent: the controller compares Git against the live cluster, reports any difference as drift, and — with self-heal enabled — reverts it on its own within seconds. The cluster becomes a projection of Git.

OpenShift GitOps, based on Argo CD, is that controller.

*In this demo*

. An application deployed from Git and managed by Argo CD
. A change made by hand on the live cluster, detected as drift with the exact difference shown
. The state defined in Git restored with a single sync
. Self-heal enabled, and the same change reverted with no one acting

*Why it matters*

=== 2 · A change made by hand — 4 min

Change the live cluster directly — scale the Deployment from one replica to three — and watch Argo CD flag the application as out of sync and show the exact difference against Git.

image::gitops-fundamentals/gitops-fundamentals-05-drift-diff.png["The Argo CD diff view with compact diff enabled: a single differing line for the parasol-claims Deployment, replicas 3 on the live cluster against replicas 1 from Git."]

*Why it matters*

The question is not whether clusters get changed by hand, but whether anyone finds out. Argo CD compares desired state against live state continuously, so the change surfaces immediately as a precise difference rather than as a surprise months later.

[source,sh,role=execute,subs="attributes+"]
----
DEV={user}-dev
oc scale deployment/parasol-claims --replicas=3 -n $DEV
oc get deployment/parasol-claims -n $DEV -o jsonpath='live replicas now: {.spec.replicas}{"\n"}'
----

*On screen* — switch to Argo CD and choose *Refresh*. The application turns *OutOfSync*, and the diff names the one line that differs.

=== 3 · Restore Git with one sync — 3 min

Apply the state defined in Git with a single sync, and confirm from the terminal that the replica count is back to one.

image::gitops-fundamentals/gitops-fundamentals-02-reconcile-loop.svg["The reconcile loop: the Application reads desired state from Git, compares it against the live cluster, and a sync applies Git whenever they differ."]

*Why it matters*

Recovery is not a rollback procedure or a change ticket. Git already holds the intended state, so bringing the cluster back into line is a single action.

*On screen* — *Sync → Synchronize*, then confirm from the terminal:

[source,sh,role=execute,subs="attributes+"]
----
DEV={user}-dev
sleep 8
oc get deployment/parasol-claims -n $DEV -o jsonpath='replicas after sync: {.spec.replicas}{"\n"}'
----

=== 4 · Self-heal — 3 min

Enable automated sync with self-heal, repeat the same manual change, and watch Argo CD revert it within seconds without anyone acting.

image::gitops-fundamentals/gitops-fundamentals-06-enable-selfheal.png["The application's Sync Policy settings in Argo CD: Enable Auto-Sync and Self Heal selected, Prune Resources left cleared."]

*Why it matters*

A manual sync demonstrates the idea; self-heal is the operating model. The controller corrects drift continuously, so the cluster cannot slowly accumulate undocumented changes.

*On screen* — application details → *Sync Policy* → enable *Auto-Sync* and *Self Heal*. Then make the same change again and take no further action:

[source,sh,role=execute,subs="attributes+"]
----
DEV={user}-dev
oc scale deployment/parasol-claims --replicas=3 -n $DEV
echo "Scaled to 3 replicas by hand — no action taken in Argo CD"
----

*What just happened*

The change was reverted in about four seconds, unattended. That is the difference between a tool that reports drift and a platform that removes it.

== Frequently asked questions

*Why is the Application created through Argo CD rather than with `oc apply`?*::
It can be applied directly. The point is that nothing else should be: the Application is the one object managed by hand, and it manages everything else.

*How quickly does self-heal revert a change?*::
It is triggered by watching the resource, so it reacts within seconds — about four seconds on this cluster. Repeated drift of the same resource is reverted with exponential back-off, so a rapid repeated test looks slower than normal operation.

*Kustomize or Helm?*::
Argo CD renders both. Kustomize suits overlays on manifests you own; Helm suits consuming a packaged chart from someone else.

*Is deploying straight from Git how production works?*::
Yes — with the promotion gate in Git rather than on the cluster: a reviewed pull request into the environment's branch or folder, instead of a person with cluster access.

*What is the difference between Refresh and Sync?*::
Refresh re-reads Git and recalculates the difference. Sync applies it. Refresh changes nothing on the cluster.

--
This polls the replica count every second and stops the moment Argo CD puts it back to 1.
// Bounded by WALL CLOCK ($SECONDS), not by an iteration count. An earlier version looped `seq 1 90`
// with `sleep 1` and claimed three minutes: true only because each pass also makes an API call, so
// the real elapsed time depended on how fast the apiserver answered. Same trap tools/ws/ws documents
// against itself in wait_healthy — a declared 1500s budget once ran 2980s. Now the sentence below is
// true by construction on any cluster.
It keeps polling for three minutes — comfortably past the controller's `90s` reconcile ceiling — so it will not run out from under you:

[source,sh,role=execute]
----
oc scale deployment/parasol-claims --replicas=3 -n $DEV >/dev/null
echo "drifted to 3 — now watch, hands off (Argo CD snaps it back):"
END=$((SECONDS + 180))
while [ "$SECONDS" -lt "$END" ]; do
  R=$(oc get deployment/parasol-claims -n $DEV -o jsonpath='{.spec.replicas}')
  echo "  $(date +%T)  replicas=$R"
  [ "$R" = "1" ] && { echo "  ✔ self-heal reverted the drift — no human touched Argo CD"; break; }
  sleep 1
done
[ "$(oc get deployment/parasol-claims -n $DEV -o jsonpath='{.spec.replicas}')" = "1" ] || \
  echo "  ⏳ still 3 after ~3 min — not broken: repeated drift backs off. See the note below."
----

*What just happened:* the edit vanished in seconds, with *nobody* pressing Sync: self-heal *watches* what Argo CD manages and corrects drift as it happens.

[cols="2,3,3",options="header"]
|===
| | Manual sync | Self-heal

| Drift is | Reported as *OutOfSync* | Reported, then reverted
| Who reverts it | You, with *Sync* | Argo CD, unasked
| How fast | When you press *Sync* | Seconds: a watch triggers it
| Choose it when | People must see a change before it lands | Git must be the only author
|===

.Slower than a few seconds? How fast self-heal is, and its backoff
[%collapsible]
====
Self-heal is *watch-triggered*: Argo CD reacts to the live change almost immediately (measured ~4 seconds here), not on a slow poll.
The controller's periodic reconcile interval — `90s` on this cluster — bounds a single, fresh drift: it is the longest one could linger if a watch event were ever missed under heavy load.

*If you drift the same resource repeatedly, expect it to get slower.*
Argo CD applies an exponential *self-heal backoff* per resource, so the first revert lands in seconds but a second or third drift of the same Deployment can take a minute or more (~147 seconds was measured on a third consecutive drift).
That is the controller refusing to fight a hot loop, not a failure — the loop above waits ~3 minutes for exactly this reason.
If you want the fast revert back, wait a couple of minutes without drifting, or press *SYNC* once in Argo CD.

Either way you *cannot out-edit Git*: the manual *Sync* button reverts drift instantly, and self-heal reverts it unasked.
====
