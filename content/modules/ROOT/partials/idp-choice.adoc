// Reusable sign-in guidance for any platform tool behind OpenShift OAuth (Dev Spaces, Argo CD,
// Developer Hub, RHACS, …). OpenShift shows a provider chooser whenever more than one identity
// provider is configured, and an attendee can pick the wrong one and hit a dead end.
// Include at SECTION level — this block uses '====', so it collides inside a [tabs] block.
//
// SAY WHAT TO CHOOSE, NEVER WHAT TO AVOID. Owner direction 2026-08-02. The previous version named
// the other provider (`rhbk`), asserted the cluster has exactly TWO providers, and stated which one
// renders first. All three are properties of the cluster we happen to install on: a customer's
// cluster may carry their corporate IdP, several others, or none of ours in that position, and the
// chooser's order is not ours to promise. Naming a provider to avoid also goes wrong the moment
// that provider is absent. The attendee needs one instruction — pick `workshop-users` — plus a way
// to recognise having picked something else. That phrasing is true on any cluster.
[NOTE]
====
*Signing in to a platform tool? Choose `workshop-users`.*

If OpenShift offers you a choice of sign-in methods, pick *`workshop-users`* and enter your workshop
username (`{user}`) and password. That is the provider that knows your workshop account.

Anything else in that list belongs to the cluster rather than to this workshop, and will not
recognise your credentials. *A wrong choice does not look like a mistake* — you get a normal-looking
username and password form, and your details are simply refused with no explanation. So if a sign-in
you expected to work keeps rejecting correct credentials, go back and pick *`workshop-users`*.

If no chooser appears at all, there is nothing to decide: just enter `{user}` and the workshop
password.

*This applies to OpenShift's own sign-in page only.* Some tools have their own front door that never
touches OpenShift — *Developer Hub* opens on *"Select a sign-in method: Guest / GitHub"*, where
*Guest* is the intended one click, and *Gitea* asks for a username and password in its own form.
Neither offers `workshop-users`, and neither is a wrong turn.
====
