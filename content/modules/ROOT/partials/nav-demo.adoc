// current, which is how a stale comment does its damage.)

// THREE entries per module — Concept + Demo arc + Presenter notes (instructor.adoc). Order and
// numbers come from /modules.yaml; tools/check-module-order.sh guards it.
//
// It was two until 2026-08-08, and the missing third was the expensive one. The demo build renders
// five pages per module but linked only two, so 78 pages sat at a URL with zero inbound links from
// anywhere in the site — reachable only by typing the path. Measured in www/demo, crawling every
// rendered page: wrapup.html and troubleshooting.html each carry 26 links and all 26 are a page
// linking to itself; instructor.html was the same before this change. Wrap-up staying unlinked is
// the deliberate call (a presenter never opens the attendee wrap-up). instructor.adoc is the
// opposite case: the measured `ws solve` lead times, the demo-mode notes, the top-questions lists,
// and warnings like "sign in to RHACS before the room, not during beat 3" live there and nowhere
// else, and an SA presenting from this rendering could not see any of it. Troubleshooting is still
// unlinked and was simply not in this change's scope — it is the next candidate, not a decision.
//
// The label is "Presenter notes", not "Instructor": the reader here is an SA in front of a
// customer, not an instructor in front of a class. The FILE stays instructor.adoc because that is
// the module template's five-file contract and the instructor rendering's own name for it.
//
// NO module-<slug>-hidden guards here, unlike nav-workshop.adoc, and that is intentional: the
// SA-Demos cockpit (gitops/workshop-config/templates/showroom-demos.yaml) is one SHARED presenter
// cockpit that injects no per-deployment module-disable attributes at all, so there is nothing for
// a guard to key on. If that ever changes, mirror nav-workshop.adoc's ifndef:: wrapping here.
