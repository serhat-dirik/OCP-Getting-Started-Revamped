// Module ORDER and NUMBERS are owned by /modules.yaml (position = number, decoupled from
// slug). tools/check-module-order.sh asserts this nav's order matches modules.yaml. To
// reorder/renumber: edit modules.yaml, then reorder these lines to match — nothing else.
//   * xref:platform-orientation/lab.adoc[1 · Platform Orientation & First App]
//
// Per-module SHOW/HIDE: each module block is wrapped in ifndef::module-<slug>-hidden[]. The
// attribute is UNDEFINED in the CI/preview builds and in an all-modules delivery, so every
// module renders by default. The attendee showroom build sets module-<slug>-hidden for each
// module the deployer disabled (bootstrap/vars.yaml modules_disabled → workshop-config
// modulesDisabledCSV → templates/showroom.yaml), so a disabled module's nav entry disappears.
//
// FOUR entries per module as of 2026-08-16 — Concept + Lab + Wrap-up + Troubleshooting. All 26
// troubleshooting.adoc pages existed already (module template's five-file contract) but were
// reachable only via inline xrefs from lab/wrapup pages, not the sidebar; this adds the menu
// entry, placed last (after Wrap-up) for quick access, inside the same ifndef guard as the rest
// of the module so a disabled module's Troubleshooting entry disappears with it.
//
// Antora derives page.previous/page.next by flattening this nav tree, so naively adding the
// entry would hijack Wrap-up's "Next" button (and the following module's Concept page's
// "Previous") into landing on Troubleshooting instead of the next module. Fixed by routing
// pagination through a custom helper — see supplemental-ui/helpers/pagination-neighbors.js and
// the overridden supplemental-ui/partials/pagination.hbs — which walks past any troubleshooting
// page in either direction. Verified in the built HTML, not assumed: e.g. jobs-batch-kueue's
// (module 6, last of "A — Foundations") Wrap-up "Next" still reads
// www/workshop/modules/pipelines-fundamentals/concept.html labeled "7.1 · Concept", and
// pipelines-fundamentals' (module 7) Concept "Previous" still reads
// www/workshop/modules/jobs-batch-kueue/wrapup.html labeled "6.3 · Wrap-up" — the pagination
// helper is shared by all three site-*.yml flavors via ui.supplemental_files, so this also fixed
// the same hijack in nav-demo.adoc once that flavor's Troubleshooting entry was added alongside
// this one. nav-instructor.adoc already carried a Troubleshooting entry (as the last item, in
// place of Wrap-up, which that flavor never lists) before this change — undocumented there, and
// the same shared helper now also skips it, changing that flavor's Instructor Guide "Next" from
// Troubleshooting to the next module's Concept page. Deliberate, not collateral: the alternative
// is a flavor-conditional helper, which is more moving parts for a rule ("Troubleshooting is a
// menu leaf, never a Next/Previous stop") that should hold everywhere it applies. Flagged to the
// project owner at the time this landed in case the instructor flavor's old chain was wanted.
