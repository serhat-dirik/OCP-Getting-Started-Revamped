= Canary fixture for credential-redaction-guard.py
:page-role: not-content

// NOT WORKSHOP CONTENT. This file exists to be FOUND. `credential-redaction-guard.py --self-test`
// scans only this file and must exit 1; if it ever exits 0 the detector has broken and a clean run
// over the real tree means nothing. It lives outside content/ so Antora never builds it.
//
// Every credential-looking string below is SYNTHETIC — invented for this fixture, matching only the
// shape and length of the real thing. Nothing here has ever authenticated to anything.
//
// EVERY SECTION CARRIES AN `EXPECT:` LINE, and the self-test asserts each one INDIVIDUALLY:
//
//   // EXPECT: <rule-name(s)>|none | <blind|flood|-> <PATTERN_NAME> — why
//
// The first field is what this section must produce (a rule name, or `none` for a section that must
// stay SILENT). The second names the ONE regex the section exists to exercise, and how to mutate it:
//   blind  — replace it with a never-matching pattern; the section's outcome MUST flip
//   flood  — replace it with an always-matching pattern; the section's outcome MUST flip
//   -      — no mutation; baseline assertion only
// A section whose outcome does NOT flip when its named pattern is mutated is not testing that
// pattern, and the self-test fails. That is the whole point: before this, blinding rule 1 still
// exited 1 because rule 2 fired, and the three "NOT an offender" sections asserted nothing at all.
// The self-test also refuses to pass unless every rule and every mutable pattern in the guard is
// named by some section, so a new rule cannot be added without a canary for it.

== Offender 1 — truncation standing in for a redaction (the original near-miss)

// EXPECT: truncation-as-redaction | blind UNAUDITABLE_STREAM_RE — found ONLY because `oc logs` is a stream whose contents we do not control; no credential word appears anywhere in the block

This is verbatim the shape that shipped: the gateway echoes the rejected key back inside the log
line, and the only thing between it and the terminal is a character count.

[source,sh]
----
oc logs deploy/parasol-agent -n user1-ai --tail=200 \
  | grep -i "Agent model call failed" | tail -1 \
  | cut -c1-200
----

== Offender 2 — the same defect in Python, on a gateway response body

// EXPECT: truncation-as-redaction | blind CREDENTIAL_CONTEXT_RE — found because the block names credential material (`Authorization`), not because of the stream

[source,sh]
----
curl -sS "$ENDPOINT/chat/completions" -H "Authorization: Bearer $GENAI_API_KEY" \
  | python3 -c 'import sys;b=sys.stdin.read();print("upstream said:\n"+b[:400])'
----

== Offender 3 — a shell parameter expansion trimming an Authorization header

// EXPECT: truncation-as-redaction | blind TRUNCATION_RE — the `${VAR:0:N}` spelling of a fixed-width trim, which is what makes this a finding at all

[source,sh]
----
AUTH_HEADER="Authorization: Bearer ${GENAI_API_KEY}"
echo "sending ${AUTH_HEADER:0:32}"
----

== Offender 4 — a literal credential pasted into a command

// EXPECT: literal-credential | blind LITERAL_KEY_RE — an `sk-` key sitting in argv rather than a $VARIABLE

[source,sh]
----
oc create secret generic maas-credentials \
  --from-literal=GENAI_API_KEY=sk-9f3b7c1d-2e4a6b8c-0d1e3f5a7b9c
----

== Offender 5 — a literal bearer token pasted into a command

// EXPECT: literal-credential | blind LITERAL_JWT_RE — the JWT half of rule 2, which had no canary at all until 2026-08-01

A pasted JWT is the same defect as a pasted key, and it is the shape the motivating near-miss was
about to print: `Received=eyJ…`.

[source,sh]
----
curl -sS "$ENDPOINT/v1/models" \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIsImtpZCI6InAxIn0.eyJzdWIiOiJwMSIsImV4cCI6MH0.c2lnbmF0dXJlLXRoYXQtbmV2ZXItc2lnbmVkLWFueXRoaW5n"
----

== NOT an offender — truncation next to an explicit redaction

// EXPECT: none | blind REDACTION_RE — silent ONLY because the `sed` is the control; the trim is just line length

The guard must stay quiet here: the `sed` is the control and the trim is only for line length. If
this section starts being reported, the guard has become too eager to be worth running.

[source,sh]
----
oc logs deploy/parasol-agent -n user1-ai --tail=200 \
  | grep -i "Agent model call failed" | tail -1 \
  | sed -E -e 's#Received=[^,]*#Received=<redacted>#g' \
           -e 's#(sk-|eyJ)[A-Za-z0-9._~+/=-]{8,}#\1<redacted>#g' \
  | cut -c1-240
----

== NOT an offender — minting a password, where the character count IS the point

// EXPECT: none | blind GENERATION_RE — silent ONLY because the input is a random-byte source: this trim generates a secret, it does not hide one

Truncating `openssl rand` output is a generator, not a fig leaf. Measured false positive on
bootstrap/install.sh and tools/ws/ws before this exemption existed.

[source,sh]
----
PASSWORD="$(openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | cut -c1-16)"
----
