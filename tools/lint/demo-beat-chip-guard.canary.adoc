= demo-beat-chip-guard canary
:page-role: fixture

Fixture for `tools/lint/demo-beat-chip-guard.py --self-test`. Every detector must fire somewhere in
this file on a line only IT fires on, and the correct forms must stay silent. If a run over this
file comes back clean, the GUARD is broken.

NOT a real page — it lives under `tools/`, outside the Antora content root, so it is never built,
and every guard that sweeps tracked `.adoc` files excludes `.canary.` paths.

Every line below carries its own expectation as a trailing marker: the positive one means the guard
has to flag that line, the negative one means it has to stay silent. (Neither is spelled out in this
paragraph, because the self-test scans the whole file for them.) A line that the guard flags without
carrying a marker is ALSO a failure — that is what keeps each detector separable, because a shape
whose defect is reported twice cannot prove which detector reported it.

An attribute line cannot carry a trailing marker: appending text after the `]` stops it being an
attribute line, so the shape would stop being the shape it is here to prove. Those expectations are
therefore declared on the comment line above, in the deferred form the shared fixture helper reads.
